01 / INDUSTRY EVOLUTION

UI 自动化测试五代演进与技术跃迁

从“死板坐标与脆弱脚本”演进到“Agent 多模态探索 + 代码级确定性回归 + VLM 视觉裁决”的第五代混合架构

GEN 1.0 · 1990s–2000s

坐标与图像录制

QTP / WinRunner / Sikuli

强绑定屏幕物理分辨率与绝对坐标 (x, y)，缺乏任何业务与 DOM 语义理解。

✕ 痛点：分辨率或字号微调即全线崩溃，无法跨机器复用。
GEN 2.0 · 2004–2016

WebDriver 协议驱动

Selenium / Appium

引入浏览器驱动与 DOM 树查询，但重度依赖冗长 XPath / CSS 层级路径与手动硬等待。

✕ 痛点：跨进程通信慢，充斥 sleep(5000)，异步动画下 Flaky 率极高。
GEN 3.0 · 2017–2022

现代内核级自等待

Playwright / Cypress

WebSocket 直连浏览器内核，原生内置 Auto-wait、getByRole 无障碍定位与 Trace 回放。

△ 瓶颈：手工编写覆盖全站路由与多视口快照的成本高昂。
GEN 4.0 · 2023–2024

纯大模型实时操作

Pure LLM Browser Agent

用自然语言直接让大模型看截图/DOM 实时推理每一步点击，免手写测试脚本。

✕ 痛点：单次耗时数分钟、Token 昂贵、结果非确定性，无法跑 CI 门禁。
GEN 5.0 · 2025+ 本方案

Agentic 混合协同架构

AI 探路 × 代码守门 × VLM

探索期用 4 通道 Agent 感知页面生成契约；回归期用 Playwright 毫秒级守门；视觉异常触发 VLM。

★ 兼具 AI 探索的高覆盖自愈力与代码级 CI 门禁的毫秒级确定性！
本方案实现的四大代际技术跃迁（Why Gen 5.0 Hybrid Architecture Wins）
① 定位范式跃迁
从易碎 XPath 跃迁至 W3C 无障碍语义树 (getByRole) 契约
② 同步机制跃迁
从硬编码 sleep 跃迁至内核级 Auto-Wait + 五步确定性去抖
③ 金字塔分层跃迁
从臃肿纯 E2E 拆解为 CT 组件挂载 (9) + E2E 旅程 (21) + 视觉快照 (24)
④ 视觉裁决跃迁
从“一像素差异即误报”进化为原生像素比对 + GPT-4o VLM 语义复核

02 / EXECUTIVE SUMMARY & CORE PARADIGM

痛点与核心设计范式：AI 动态探路 × Playwright 确定性守门

解决“传统脚本易碎难维护”与“纯 AI 执行慢贵且不确定”的两难困境，让最擅长的技术处理最匹配的生命周期阶段

INDUSTRY DILEMMA · 行业三大核心痛点

为什么传统 UI 自动化与纯 AI 测试都难以落地？

01 · 手写选择器极度脆弱，前端改样式即崩

传统脚本耦合 CSS 类名或 DOM 层级，缺乏前置契约探测；同名按钮与多语言切换频繁触发 Strict Mode 冲突。

02 · 纯 AI Agent 跑回归：慢、贵、不可复现

每次回归都让大模型看图操作浏览器，单条用例耗时数十秒且每次路径不同，无法作为高并发 PR 准入门禁。

03 · 视觉像素对比“狼来了”误报泛滥

5 秒轮播图、CSS 动画、懒加载图片以及 macOS 与 Linux 字体抗锯齿微差，导致像素级对比频繁误报。

OUR SOLUTION · 三阶段正交混合范式

探索用 AI 负责“广度”，回归用代码负责“速度”，视觉请 VLM 负责“降噪”

Phase A · 发现与生成期：多通道 AI 探索（重感知） 4 Channels

由 ui-test-discovery 按需调度 AST、Browser Use、playwright-cli 与 Computer Use，穿透扫码登录与系统弹窗，沉淀结构化发现契约与三层定位策略。

Phase B · 高频回归期：Playwright 纯代码守门（重速度） 0 Token · ms 级

将探索成果 100% 固化为 Git 纳管的 TypeScript 测试规格（9 CT + 21 E2E + 24 Visual），每次 PR 触发毫秒级确定性执行，支持 Azure 云端 10 Workers 并发。

Phase C · 视觉裁决期：像素 + GPT-4o VLM 双层漏斗（重精准） Smart Noise Filter

95% 常规回归走免费原生像素比对；仅当像素比对失败且开启 VLM_REVIEW=true 时，调用 GPT-4o Vision 区分抗锯齿噪点与真实 UI 崩坏。

02B / CORE ENGINE COMPARISON

三大核心引擎对比：Playwright · Browser Use · Computer Use

厘清“网页确定性代码引擎”、“AI 实时浏览器协作引擎”与“AI 操作系统桌面引擎”的能力边界与黄金分工

ENGINE 01 · 确定性回归守门员

Playwright

控制边界：浏览器网页内部（DOM 树 / 无障碍树 / 网络层）

底层原理：通过浏览器内核协议（CDP）直接运行编译好的 .spec.ts 测试代码，内置 Auto-Wait 自动等待。

✓ 核心优势：毫秒级极速执行、0 Token 消耗、结果 100% 确定可复现，天然支持云端无头（Headless CI）高并发。

! 能力边界：无法操作浏览器外的系统原生文件框；遇到首次扫码/滑块登录需提前准备凭证。
ENGINE 02 · 实时网页侦察兵

Browser Use (MCP)

控制边界：开发者已打开的 Chrome / Edge 真实标签页

底层原理：AI 直接接管真人正在使用的浏览器标签页，支持“真人扫码登录 → AI 无缝接手探查”的人机交接。

✓ 核心优势：免密穿透企业微信 / SSO / MFA 登录墙；可随时注入 JS 探针采集动态渲染后的 DOM 与存储状态。

! 能力边界：仍受限于网页沙盒内部（看不见操作系统弹窗）；单步需 AI 参与，不适合跑海量日常回归。
ENGINE 03 · 跨界破局特种兵

Computer Use (MCP)

控制边界：整个电脑操作系统桌面与原生窗口

底层原理：跳出浏览器限制，站在 macOS / Windows 操作系统桌面视角，模拟真人鼠标键盘操控任意系统窗口。

✓ 核心优势：唯一能操作 <input type=file> 系统原生文件夹窗口、OS 权限框、系统打印框及桌面应用的引擎。

! 能力边界：强依赖图形桌面环境且耗时较长，探明路径后需翻译为 Playwright 标准接口才能上云端 CI。
四大核心维度横向速查表（为什么三者缺一不可？）
对比维度 Playwright（确定性代码引擎） Browser Use（AI 实时浏览器） Computer Use（AI 桌面引擎）
操控视野 网页内部（DOM 树 / 无障碍树 / 网络） 真实 Chrome/Edge 标签页（含已登录态） 整个电脑桌面屏幕与操作系统原生窗口
登录与系统弹窗 依赖已导出的登录凭证 / 无法点系统弹窗 支持真人扫码/MFA 交接 / 无法点系统弹窗 通吃 macOS/Win 原生文件选择框与权限框
在本方案中的分工 【回归期主力】毫秒级、0 Token 跑 CI 门禁 【探索期前锋】免密进场、动态采集页面结构 【探索期特种兵】跨越浏览器边界打通死角

04 / MULTI-CHANNEL INTELLIGENT EXPLORATION

四通道智能站点探索机制：Static AST / Browser Use / playwright-cli / Computer Use

由 ui-test-discovery 按需渐进调度四条互补通道，既能毫秒级白盒扫描源码，也能跨出浏览器操控系统级原生窗口

CHANNEL 01 · 默认首选

Static AST 源码分析

零运行时开销 · 秒级全景扫描

触发时机：存在本地前端源码（src/）时默认第一步执行。

探查内容：解析 App.tsx 8 条路由、9 个组件 Props 接口、locales/zh.json & en.json 双语词条及 localStorage 键名。

局限接力：看不见运行时真实渲染位置与登录拦截 ──► 移交通道 02/03。
CHANNEL 02 · 人机协同

Browser Use (MCP)

复用真人登录态 · 实时 DOM 探针

触发时机：遇到 SSO / 企业微信扫码 / MFA 验证码，或复杂的 Portal / Shadow DOM 动态组件。

探查内容：通过 manage_user_tab 接管已登录标签页导出 storageState，并用 run_javascript 检测同名按钮冲突。

局限接力：受限于浏览器内部，无法点击系统原生弹窗 ──► 移交通道 03/04。
CHANNEL 03 · 干净沙盒

playwright-cli 引擎

无障碍语义树快照 · 自动录代码

触发时机：仅提供线上/测试环境 URL 的黑盒探索，或需在独立沙盒中录制标准交互轨迹。

探查内容：调用 snapshot 导出 YAML 无障碍语义树（含元素 ref），边执行 fill/click 边自动映射为 Playwright 代码草稿。

局限接力：遇到跳出 DOM 的 OS 原生文件框会卡住 ──► 升级通道 04。
CHANNEL 04 · 跨界破局

Computer Use (MCP)

OS 桌面级 CUA · 突破浏览器围墙

触发时机：网页操作触发了浏览器 DOM 之外的操作系统原生窗口或桌面端协同场景。

探查内容：通过桌面级 exec_js 操控 macOS Finder / Windows 原生文件选择框、OS 级摄像头/定位权限弹窗及系统打印对话框。

核心使命：帮团队走完探索闭环，随后收敛映射为无头 Playwright API！
★ 确定性收敛原则（Deterministic Convergence Rule）：探索期多模态破局，回归期纯代码收敛
Browser Use 扫码登录 ──► 固化为 storageState；Computer Use 原生选文件/点权限 ──► 固化为 locator.setInputFiles() 与 context.grantPermissions()，确保 Linux 无头 CI 100% 独立运行。

03 · playwright-cli 录制

第四棒 · 桌面视角破局

04 · Computer Use 控桌面

执行动作：启动桌面级 cua 引擎看到整个电脑屏幕，在 macOS 原生文件窗口中选中 passport-sample.jpg 并点击“打开”。

✓ 闭环验证：文件成功回填网页，探明网页随后出现 role="status"（“护照 OCR 识别成功”），点击主区域“提交申请”走完闭环！

探索通关 ──► 收敛生成纯代码剧本
★ 最终收敛产物：生成的 tests/e2e/visa-apply.spec.ts（在无屏幕 Linux 云端 CI 零人工、毫秒级全自动运行）

page.getByRole('main').getByRole('button', { name: '提交申请' })
③ 原生文件框收敛为底层文件直塞

05 / SIX-GATE QUALITY PIPELINE

端到端六步质量门控工作流（6-Gate Pipeline）

从用户自然语言意图到结构化报告落盘，6 道刚性门控确保多 Agent 协作不串线、不漏检、不污染业务代码

GATE 01 Owner: ui-test

意图分流门控（Routing Gate）

识别用户请求属于组件测试（CT）、端到端测试（E2E）、视觉回归（Visual）还是云端门禁治理（Governance）。默认路径保持轻量直达，未请求云端或 VLM 时绝不强行加载重型依赖。

产出：精准子 Agent 调度指令与上下文边界
GATE 02 Owner: ui-test-discovery

缓存新鲜度门控（Freshness Gate）

检查 docs/DEEP_DISCOVERY_REPORT.md 顶部内嵌的 <!-- git-commit: abc1234 --> 指纹。只要自上次探索以来 src/ 目录无文件变更，直接秒级复用缓存报告，避免重复扫盘。

产出：DEEP_DISCOVERY_REPORT.md + LOCATOR_STRATEGY
GATE 03 Owner: playwright-config

唯一配置所有权门控（Config Gate）

严格锁定 playwright.config.ts、playwright-ct.config.ts、playwright.service.config.ts 及 tests/fixtures/ 的唯一修改权，彻底杜绝多个测试 Agent 互相覆盖端口、视口或超时配置。

产出：3 套标准化 Config + test-helpers.ts 共享夹具
GATE 04 Owner: CT / E2E / Visual

生成质量门控（Generation Gate）

强制生成代码遵循三层定位优先级（首选 Landmark + getByRole，严禁脆弱 XPath 与 waitForTimeout），并在每个 beforeEach 中清空 localStorage、挂载 pageerror 异常监听器。

产出：9 CT Specs + 6 E2E Specs + 1 Visual Spec
GATE 05 Owner: Runner + VLM

执行与双层裁决门控（Execution Gate）

本地或 Azure 云端执行测试套件；视觉对比失败时严禁自动运行 --update-snapshots 掩盖问题，按需触发 GPT-4o VLM 语义复核（置信度 ≥ 0.7 过滤渲染噪点）。

产出：playwright-report + vlm-report.json 裁决明细

CROSS-OS BASELINE AUTHORITY · 跨平台基线治理

解决 macOS (-darwin) 与 Linux (-linux) 字体渲染不一致难题

基线权威模式 适用场景 工程规则与快照后缀治理
模式 A · Local-Only 个人开发与本地快速调试 本地生成并比对 *-darwin.png，不阻塞云端流水线
模式 B · Azure Linux 权威 团队 PR 准入门禁（推荐） 统一通过云端/容器 Linux 浏览器生成权威基线，消除 OS 差异
模式 C · Hybrid 混合复核 跨端渐进迁移期 本地开发自检 + CI 走 Linux 基线配合 VLM 过滤跨平台字重微差
★ 根因治理：Playwright 默认将 process.platform 拼入快照文件名，显式权威策略避免了在 Linux CI 中因找不到 -linux.png 而全军覆没。
SECURITY & CREDENTIAL REDLINE · 安全与成本护栏

企业级凭据隔离与云端韧性设计
